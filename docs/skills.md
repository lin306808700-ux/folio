# Skill 编写指南

Skill 是按需加载的 Markdown 指令，用于给模型提供特定领域的工作方法。它适合表达流程、检查清单和决策规则，不适合绕过工具权限或隐藏可执行代码。

## 存放位置

用户 Skill 默认存放在 Muse 配置目录的 `skills/` 下。实际目录由 `src/main/muse/config.js` 决定；不要在扩展中假设固定的用户主目录。

## 建议结构

```markdown
# Skill 名称

一句话说明这个 Skill 解决什么问题，以及何时应该使用。

## 输入

- 必需上下文
- 可选信息

## 工作流程

1. 检查前置条件。
2. 执行可验证的步骤。
3. 汇总结果与剩余风险。

## 安全边界

- 哪些动作需要确认
- 哪些目录或数据不可触碰

## 完成标准

- 可观测、可测试的结果
```

## 编写原则

- 开头明确触发场景和不适用场景。
- 使用短步骤和可验证结果，避免宽泛人格描述。
- 不要求模型忽略用户、系统、安全或工作区规则。
- 不在 Skill 中保存 API Key、Cookie、个人数据或机器绝对路径。
- 涉及外部写操作时，明确授权点、失败恢复和幂等要求。
- 示例应能在干净工作区复现。

## 分层约定

项目内部把 Skill 按作用划分为质量规则、工作流规则和系统能力。分层只影响组织和加载策略，不改变安全权限。任何 Skill 调用工具时仍受工具参数校验、工作区沙箱和命令策略约束。

## 发布检查

- 在全新会话测试触发条件；
- 测试缺少输入、用户拒绝授权和工具失败；
- 检查输出中没有内部协议、原始 JSON 或敏感数据；
- 声明兼容的 Muse 版本和变更记录。
