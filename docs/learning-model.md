# 学习模型设计

本文定义 Folio 学习子系统的知识模型、进度口径与展开语义。实现分布在
`src/main/muse/learning-maps.js`、`learning-prompts.js`、`LearningMapPage.tsx`
与 `LearningBookReader.tsx`。改动这些行为前请先读本文。

## 要解决的问题

学习者在领域内自由游走时会遇到四类失焦：

1. **全局感丢失** —— 下钻越深，越不知道自己在这个领域里的位置。
2. **分母缺失** —— 知道学了什么，不知道还剩多少。
3. **只有纵深没有生态** —— 能往下挖，但看不到同一层的同类、替代方案与相邻概念。
4. **领域的墙不可见** —— 一个知识点通向哪个别的领域，无从得知。

根因是同一个：**知识图谱的节点只能从「用户已经好奇的地方」长出来，所以它永远长不出
「你不知道自己不知道」的部分。** 全局感不可能由个人探索自己生长出来，它必须来自一份
独立于用户存在的领域骨架。

## 三层模型

| 层 | 名称 | 职责 | 谁生成 |
| --- | --- | --- | --- |
| 0 | 领域骨架 canon | 给出**分母**：该领域大致包含哪些知识点 | AI，按关键词生成 |
| 1 | 探索图 personal | 给出**分子**：用户真正走到哪一步 | 用户 + 下钻/平铺 |
| 2 | 连接边 edges | 给出**横向与跨域**：前置、同类、门户 | AI 提议，写回节点 |

### 节点字段

```js
{
  id, parentId, title,
  status,                  // unexplored | learning | understood | verified
  verifiedBy,              // '' | 'manual' | 'quiz'
  origin,                  // 'canon' | 'user'  —— 骨架节点还是用户自建
  edges: [                 // 第 2 层：非树边，节点只有 parentId 时图谱是孤岛
    { type: 'prereq' | 'peer' | 'portal', targetNodeId?, targetMapId?, targetTitle, note }
  ],
  lastReviewedAt,          // 最近一次状态变更或验收通过的时间，用于衰减
  summary, evidence, nextStep, content, qa, quiz,
  createdAt, updatedAt
}
```

### 图谱字段

```js
{
  id, title, description, builtIn, currentNodeId, nodes,
  canon: { generatedAt, scaleEstimate, source },   // 骨架的生成记录
  createdAt, updatedAt
}
```

## 进度口径：两个数字，不是一个

只看一个百分比会掩盖「看过但没吃透」的量。Folio 同时给出两个：

```
覆盖度 coverage = 进入过的节点数 / 分母
掌握度 mastery  = Σ(节点有效分数) / 分母
```

- **分母**：存在 canon 节点时取 canon 节点数（`basedOn: 'canon'`）；
  旧图谱没有骨架，退化为全部节点数（`basedOn: 'graph'`），保证历史数据仍然可读。
- **进入过**：`status !== 'unexplored'`。注意不能用「有没有正文」判定 ——
  后台预生成会往未学习节点写正文，用正文判定会让覆盖度虚高。
- **有效分数**：状态权重 × 时间衰减。

### 状态权重与衰减

| status | 权重 |
| --- | --- |
| unexplored | 0 |
| learning | 0.35 |
| understood | 0.7 |
| verified | 1.0 |

衰减只作用于已获得的分数，下限 0.5，即最多打五折，不会把老数据归零：

```
decay   = max(0.5, 0.5 ^ (距上次复习天数 / 60))
有效分数 = 权重 × decay
```

`lastReviewedAt` 缺省的节点不衰减（历史数据不被凭空打折）。
有效分数低于权重 85% 的节点计入 `stale`，也就是「该复习了」。

两个数字的**差值**才是行动指令：差得越多，说明「看过但没吃透」的越多。

## 展开的四种方向

圈选工具条提供四个动作。这不是并列的功能，是四个正交方向。

| 方向 | 动作 | 语义 | 产物 |
| --- | --- | --- | --- |
| ↓ 下钻 | drill | 它的内部机制是什么 | 子节点 |
| → 平铺 | spread | 同层还有哪些同类 / 替代方案 | 兄弟节点 + `peer` 边 |
| ↑ 回溯 | — | 它挂在哪套体系下 | 现有面包屑导航，不调模型 |
| 🚪 跨域 | portal | 它通向哪个别的领域 | `portal` 边 |

平铺把新节点挂在**当前节点的父节点下**（真正的同层），而不是当前节点下 ——
挂错地方会让树变成纵深链，横向语义丢失。当前节点是根节点时降级为子节点。

跨域不新建图谱，只在当前节点上写一条 `portal` 边，记录目标领域名与桥梁概念。
这样领域之间的墙可以在不污染当前图谱结构的前提下被标注出来。

## 测验的三个层级

测验不只是关卡，更是**测量工具** —— 色块的分数必须有数据来源。

| 层级 | 范围 | 考什么 |
| --- | --- | --- |
| 章节级 | 单节点正文 | 机制与取舍（已有：`quiz` / `grade`） |
| 分支级 | 某分支下所有已学节点混合 | 体系关系：这两个概念是什么关系、该用哪个 |
| 领域级 | 灰区 + 衰减区优先抽样 | 覆盖诊断，输出「下一步去哪」 |

## 数据兼容

老数据没有 `edges` / `origin` / `lastReviewedAt` / `canon`。读取时在 `load()`
里就地补默认值（`edges: []`、`origin: 'user'`、`lastReviewedAt: ''`），
下次写入自然落盘。**不做破坏性迁移，不写迁移脚本**；`listMeta()` 的派生进度
按 `basedOn` 自动降级。

## 内置完全体示例

随仓库发布的 `src/main/muse/builtin-learning-maps.demo.json` 不是一份空白图谱，而是一份
**伪造的三个月自学现场记录**（领域：AI Agent 实现原理）：

| 部分 | 规模 | 说明 |
| --- | --- | --- |
| 用户自建 | 22 | 第 1–5 周靠下钻自己长出的章节，以及后续平铺/自建的节点，`origin: 'user'` |
| 领域骨架 | 59 | 第 6 周一次铺出，10 个板块，`origin: 'canon'`，**这就是分母** |
| 当前进度 | 覆盖 52.5% / 掌握 23.5% | 进入过 31 / 59，差值 29% 即「看过但没吃透」，20 个已衰减 |
| 连接边 | 29 条 | peer 11 / prereq 5 / portal 13 |
| 圈选问答 | 14 条 | 分布在 10 个节点；圈选原句必须是正文里真实存在的片段 |
| 章节验收 | 5 次 | 含两条「首次未通过 → 触发阅读引导 → 后来重测通过」的记录 |
| 正文 | 81 章 / 89152 字 | **全部节点都有正文**，后台预生成队列为空，示例不依赖任何 AI 调用 |

十个板块是：基础前提、循环范式全景、长上下文管理、工具生态、记忆与检索、
多智能体协作、安全与监督、评估与上线、协议与生态、失败模式与反模式。
其中**长上下文管理、协议与生态、失败模式与反模式**是个人探索几乎不会自己长出来的三块 ——
它们的收益或风险只在规模出现后才显现，所以在「不看地图就不知道自己缺什么」这件事上，
这三块比其余七块更能说明骨架的价值。

为什么需要这份伪造数据：Folio 的主张（有分母、有横向生态、有色块与复习提醒）
只有在一份**被真实用过一段时间**的图谱上才看得出来 —— 空图谱展示不了衰减，
也展示不了「看过但没吃透」的差值。

**骨架规模本身就是内容的一部分。** 早期版本只铺了 7 个板块 30 个知识点，
覆盖度算出来是 53% —— 那个数字不是「学得好」，而是分母太小。
骨架不完整时，所有百分比都只是比例尺错的仪表盘。所以
`canon.scaleEstimate`（AI 对领域真实规模的估计，示例中为 150）**必须大于**实际铺出的节点数：
它诚实地告诉用户「骨架本身也是不完整的」。

## 知识生成契约

「课要权威、结构要完整」不能靠形容词，只能翻译成可检查的约束。契约在
`src/main/muse/learning-prompts.js`，是交互式（`muse-handlers`）与后台预生成
（`learning-prefetch`）共用的唯一来源 —— 两条链路必须产出同一风格，否则用户手动
写的章节与后台写的章节会在「和邻章的分工」上明显不一致。

### 骨架（`kind: 'skeleton'`）

不只要「列出一些知识点」，而是被一份**八类覆盖维度**逼着交出完整结构：

1. 基础概念与前提（定义、术语、约束）　5. 质量与评估（怎么度量）
2. 核心机制与原理（怎么运作）　　　　　6. 风险与失败模式（会怎么坏）
3. 范式与方法谱系（有哪些路线）　　　　7. 边界与争议（哪些还有分歧）
4. 工具、协议与实践（怎么做）　　　　　8. 相邻领域接口（通向哪里）

规模要求 6–10 个一级板块、每板块 4–7 个知识点、合计 45–70 个；
**允许第三层**，但只在「该概念确实有公认的分解方式」时才用 —— 提示词里写明了
「不要为了凑层数而拆，凑出来的层级会让分母虚高」。渲染层的
`parseSkeletonNodes` 递归写入三层，并对深度与总量设上限（3 层 / 120 节点）。

### 正文（`kind: 'content'`）

八条要求里，真正让它区别于普通「写一篇介绍」的是这四条：

| 要求 | 为什么 |
| --- | --- |
| 第一条要点必须是**可判定的定义**：是什么、不是什么、与相邻概念的界线 | 权威性的下限；用同义词替换充当定义等于没有定义 |
| 讲机制必须给**具体量级**：数字、阈值、复杂度、协议字段、代价 | 「性能更好」无法验证，也无法在后续轮次里被引用 |
| 区分**公认结论 / 主流做法 / 仍有分歧**三档 | 把一家之言写成普遍规律，是科普与教材的分水岭 |
| **不编造** API、版本号、论文、标准编号、基准数字 | 宁可少一个数字，不可多一条假的；不确定就说不确定 |

另外两条工程性的：第三节实例按主题自适应（工程主题用 `### 代码实例`，
人文社科用 `### 实例与证据`），以及**注入本书目录与同层邻居**。

后一条是结构完整的关键。此前 `content` 请求只带 `mapTitle / nodePath / nodeTitle`，
没有邻章上下文 —— 结果是每一章都会把背景从零重讲一遍，章节之间必然重叠。
现在两条链路都会带上：

- `outlineTitles` —— 纯标题缩进树（不带 nodeId，避免模型把内部 id 写进正文）
- `siblingTitles` —— 同层章节，用来区分「这一章别写成隔壁那一章」

标题层级统一用 `###`，与仓库中已有的全部章节保持一致（节点名已由页面标题承担，
正文不需要再用标题重复一次）。

### 种子格式与时间约定

- 种子节点与 `learning-maps.js` 的节点结构一致，三层模型的字段全部保留：
  节点上的 `origin` / `edges` / `qa` / `quiz` / `lastReviewedAt` / `verifiedBy`，
  以及图谱上的 `canon`。**丢字段等于把示例退化成平面树。**
- 时间可以写成**相对天数**（`createdDaysAgo` / `reviewedDaysAgo`，问答与验收条目用
  `daysAgo`），由 `learning-seeds.js` 在注入时物化成绝对时刻。必须这样做的原因：
  衰减与「该复习了」只有相对今天才成立，写死绝对时间会让示例随日历一起腐烂。
- 种子没写复习时间的节点保持 `lastReviewedAt: ''`，即**不衰减** —— 不允许拿播种时刻
  当复习时刻，否则老图谱一开箱就集体过期。
- **正文与状态是解耦的两件事**：`content` 表示「这一页已经写好了」，
  `status` 表示「我学到哪一步了」，两者互不推导。内置示例给全部 81 个节点都预置了正文，
  其中 28 个骨架节点的 `status` 仍是 `unexplored` —— 这正是后台预生成管线的正常产物
  （`buildQueue` 的判据是 `!content`，不看状态与来源）。
  这样做的实际收益是：示例在**完全无法调用 AI 的环境**下依然完整，
  不会出现点开是空页、或按钮必然失败的节点；而覆盖度只认状态，预置正文不会让它虚高。

### 一个真实踩过的坑：报错被当成正文落盘

额度耗尽或鉴权失败时，`qodercli` 会把错误写进 **stdout**：

```
Qoder API error: FORBIDDEN - {"code":"112","message":"{\"pricingUrl\":\"…\"}"}
```

流式读取时它与正常输出无从区分，于是被当作正文一路传下去，最后落进 `content`。
这造成过一个连锁故障，现在由三层共同兜住：

| 层 | 措施 |
| --- | --- |
| `model-provider.js` | 用 `src/shared/ai-error.js` 的判据识别并**抛错**，让失败的调用不再表现为成功 |
| `learning-prefetch.js` | 落盘前再判一次，命中就丢弃并按失败退避，留待恢复后重跑 |
| `seedBuiltinMaps` | 把「命中判据的正文」视同没有正文，使内置种子能够**修复**已污染的数据 |

第三层是必需的：那段垃圾**非空**，只会被当成「已写好」，从而永久挡住种子回填 ——
演示图谱就曾有 16 个节点卡在这个状态里，界面显示的是报错而不是章节。

判据本身刻意收得很紧（长度上限 400 字 + 窄特征），因为它的错误方向不对称：
漏判只是少拦一次，误判会丢掉正常生成的内容、甚至覆盖用户手写的笔记。
所以「讲 403 FORBIDDEN 的章节」必须不被判为报错 —— 这条有单测守着。
- 重新生成：`node scripts/generate-builtin-3month-demo.js`，数据源在
  `scripts/builtin-agent-3month/`（`outline.js` 树与时间线、`dialogue.js` 问答与验收，
  以及 `chapters.md` + `chapters-canon-*.md` 正文）。生成脚本会复用上一版文件里的既有正文，
  可重复执行。正文按主题拆成多个 markdown 文件，是为了让增删一章的 diff 不牵连整份文件。
- 目录体检：`node scripts/verify-demo.js` 会把示例注入临时 store，打印正文完整性、
  双指标、悬空边与十板块的进入情况 —— 改动示例后先跑它，再跑测试。
- 替换内置图谱要**同时**改 id 与 `DEPRECATED_BUILTIN_IDS`，旧图谱启动时移除。
